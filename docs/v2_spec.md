# qr-inventory-system Ver2.0 仕様書

## Ver2.0の目的

Ver2.0では、スマートフォンやPCブラウザから利用できるWebアプリ版に開発対象を集約する。
現場担当者がQRコードを読み取り、端末に専用アプリをインストールせずに入庫・出庫・在庫確認を行えることを主目的とする。

主な目的は以下とする。

- Webブラウザから操作できる画面に利用導線を一本化する。
- スマートフォンでのQRコード読み取りと現場入力をしやすくする。
- PCブラウザでは品目一覧、履歴確認、マスタ管理、バックアップなどの管理作業を行いやすくする。
- 小規模な社内利用から、将来的な外部公開・販売を見据えた構成へ段階的に移行する。

## アプリケーション構成

Ver2.0はWebブラウザ利用を前提とする。
旧CUI版・旧デスクトップGUI版のエントリポイントは環境整理のため削除し、同じ機能をWeb画面から扱う方針に統一する。

| 項目 | Ver2.0 |
| --- | --- |
| 利用形態 | Webブラウザ |
| 主な端末 | PC / スマートフォン / タブレット |
| 起動方法 | `uvicorn` でWebサーバー起動 |
| QRコード利用 | スマートフォンカメラで読み取り、Web画面へ反映 |
| 認証 | 環境変数ベースの管理者ログインとセッション管理を実装済み。ユーザー別ログイン、ロール管理、パスワードハッシュ化は将来対応 |
| 公開範囲 | ローカルLAN、トンネル経由確認、VPS公開へ段階移行 |
| DB | 当面SQLite、将来PostgreSQLへ移行可能に設計 |

## 現在の実装状況

現時点では Ver2.0 Web版の主要機能を実装済み。
本仕様書では、実装済みの範囲と今後の設計方針を分けて扱う。

### 実装済み

- FastAPI / Jinja2 によるWeb画面。
- 品目一覧、品目検索、品目詳細、入庫、出庫、最低在庫アラート。
- 管理者パスワードによるログイン、セッションCookieによるログイン状態保持、ログアウト。
- 管理者ログイン後の品目登録、品目編集、品目削除、棚卸修正。
- CSV出力、QRコード生成、ラベル印刷用HTML生成。
- DBバックアップ、DB復旧、危険操作前の自動バックアップ。
- Web操作の操作ログ・監査ログ表示。
- 品目一覧と品目検索の検索、絞り込み、並び替え。
- `/scan/{item_id}` 形式のQRスキャン運用。

### 未実装または限定実装

- CSV取込の実運用フロー。画面とDB側の処理は整備中だが、Web画面からの取込実行・プレビュー確定フローは限定実装。
- ユーザーID単位のログイン管理。
- 管理者、通常ユーザー、閲覧専用などのロール管理。
- パスワードのDB保存とハッシュ化管理。
- CSRF対策の明文化とトークン導入。
- ブラウザのカメラAPIを使ったWeb画面内QR読み取り。
- PostgreSQL対応とマイグレーション管理。

### 将来対応

- 複数ユーザー管理と権限別メニュー制御。
- 会社、拠点、テナント単位のデータ分離。
- VPS / クラウド本番運用を前提にしたPostgreSQL移行。
- 監査ログ、バックアップ、障害対応、利用規約、ライセンス確認の販売向け強化。

## Webアプリ方針

Webアプリは、業務ロジックとDB構造を保守しやすい形に整理しながら、HTTP経由で操作できるUIを提供する。
サーバーサイドレンダリングを基本とし、FastAPI、Jinja2、HTML/CSS/JavaScriptで画面を構築する。

方針は以下とする。

- 在庫操作、品目検索、履歴表示、最低在庫アラートなどの共通ロジックは再利用しやすい形に整理する。
- Web固有の処理（ルーティング、テンプレート、フォーム検証、認証）はDBアクセス層と分離する。
- 画面遷移は単純で、現場作業者が迷わない構成にする。
- 初期リリースでは複雑なSPA化を避け、保守しやすい構成を優先する。

## スマートフォン対応方針

スマートフォン対応では、現場で片手操作しやすい画面とQRコード読み取りを重視する。

- レスポンシブデザインを採用し、幅の狭い画面でも主要操作を行えるようにする。
- 入庫・出庫・品目検索はスマートフォンの操作を最優先に設計する。
- ボタン、入力欄、リンクはタップしやすいサイズにする。
- QRコード読み取りはブラウザのカメラAPI利用を検討する。
- カメラAPIが使えない端末向けに、品目IDやQRコード文字列の手入力も残す。
- 通信が不安定な現場を想定し、送信後の結果表示、二重送信防止、エラー表示を明確にする。

## 違うWi-Fiから利用する方法

ローカルPCで起動したWebアプリは、通常は同じLAN内からのアクセスに限定される。
違うWi-Fi、社外、モバイル回線から利用する場合は、以下のいずれかの方法を検討する。

1. **ngrok / Cloudflare Tunnel で一時的に公開する**
   - 開発・デモ・外部確認向け。
   - ローカルPCで起動したWebアプリへインターネット経由でアクセスできる。
   - URLが外部に公開されるため、必ず認証を有効化する。

2. **VPSへデプロイする**
   - 本番運用・継続利用向け。
   - HTTPS、リバースプロキシ、ファイアウォール、バックアップを前提に構築する。
   - 将来的なPostgreSQL移行や監視の導入を検討する。

## セキュリティ方針

- 管理者機能はログイン必須にする。
- 管理者パスワードは `QR_INVENTORY_ADMIN_PASSWORD` で設定し、初期値のまま本番利用しない。
- セッションCookie署名キーは `QR_INVENTORY_SESSION_SECRET` で設定する。
- 外部公開時は HTTPS とリバースプロキシを利用する。
- CSV取込、DB復旧、品目削除など影響の大きい操作では、事前バックアップと操作ログを残す。
- 将来、CSRFトークン、ユーザー別認証、ロール管理、パスワードハッシュ化を追加する。

## DB方針

当面はSQLiteを継続利用する。
DBファイルは `QR_INVENTORY_DB_PATH` で保存先を変更できるようにし、バックアップと復旧手順を明確にする。

将来的に利用人数、データ量、同時操作数が増える場合は、PostgreSQLへの移行を検討する。
その際は、接続文字列、マイグレーション、バックアップ、監視、権限管理を別途設計する。
